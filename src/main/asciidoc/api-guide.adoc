[[introduction]]
== Introduction

The application's API is GraphQL, at `/api/graphql` (see the GraphQL API guide). The plain HTTP endpoints are these. All
but registration and personal links need an access token from Keycloak; errors are `{"error": "..."}` with the status that
fits (`400` for an invalid request, `401`/`403` for the wrong or no token, `429` for too many tries, `503` when something this
server depends on is down).

[[registration]]
== Registration

Registering an account is done here; Keycloak's own registration is off. The endpoints are public and guarded by
Cloudflare Turnstile and rate limits. An address that already has an account gets the same answer, and an email about it.

[[external]]
== Other applications that take payments

An application where members pay (a shop, say) tells Medlemskap that someone paid, and can ask whether an address has an
account and a membership. Each such application has its own Keycloak service client with the role `PAYMENT` on
`fgv-membership`; the first is `fgv-external-payment-service`. It gets a token with the client credentials grant and sends it
as `Authorization: Bearer ...`. The API is on its own hostname (`API_HOST` in the deployment).

=== Tell that someone paid

`POST /api/external/payments`

The address is the identifier. The *spexare* is found in Spexregister by the address, or created there (not published). The
*account* is found in Keycloak by the address; if there is none, one is created with the default access of the kind of
membership (see *Default access* in the web), and the person gets an email saying so and, from the login service, a link to
choose a password. An account that exists is never changed. The payment is recorded as a matched payment request, the
membership counts at once, the member gets a receipt, and the administrators are emailed.

`paymentReference` is the application's own id for the payment (an order or transaction id). It is kept with the payment,
shown to the treasurer and in the bookkeeping export, and the same id from the same application is the same payment, so
retrying is safe. Without one nothing protects against being told twice, except that a person who is a member for the year
already is not recorded again.

[[exports]]
== Excel exports

`GET /api/exports/members.xlsx?year=` (`BOARD`): the year's members, by name. `GET /api/exports/payments.xlsx?year=`
(`TREASURER`): the year's payments for the bookkeeping, with date, amount, reference, member, how, what they were matched to
and the other application's payment id. Both answer an Excel workbook (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`).

[[spexregister]]
== Notice from Spexregister

`POST /api/sync/spexare-deleted` with a token holding `SYNC`: Spexregister tells that a spexare was deleted. Medlemskap
keeps the memberships and payments, which are bookkeeping records, and marks them as belonging to a deleted spexare.
